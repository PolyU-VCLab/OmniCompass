# OmniCompass 评测 Skill：中文审核版

名称：`omnicompass-eval`。
用途：指导代理使用本仓库配置、运行、续跑和评分 VL/AV 评测，支持 API 和本地模型；不用于训练或修改标注。

## 准备评测

使用现有工具，不另写 Prompt 构造器或评分器。先找到包含 `run.sh`、
`code/release_tools.py` 和 `README.md` 的工具根目录；找不到时询问仓库位置。
以下路径均相对该目录。

阅读 `README.md` 和 `bash run.sh --help`。准备输入、续跑、排错或接入自定义
模型时，查阅 `docs/evaluation_protocol.md` 的对应章节。

根据用户要求和已有配置，确认数据路径、准确模型 ID、API 地址或本地服务、
track、任务、参考设置、帧数或 FPS、生成预算、并发和输出目录。
只询问缺失的决策；付费调用前展示命令和请求数量，已有明确授权不必重复询问。
下载仓库或要求配置环境，不等于授权模型调用、下载权重或全量评测。

按 README 安装依赖、解包数据，检查所选媒体和 `KNOWN_ISSUES.md`，不转码或替换
发布媒体。按实际选中的题目和设置统计请求量，不只根据视频数估算。
密钥放在指定环境变量中，不打印、不写入命令、提交文件或报告。

兼容 API 只配置地址、模型 ID 和密钥，不改 runner。本地模型参考 README 的
Qwen3.5-9B 示例或对应模型的官方部署说明，确认 GPU 资源及图片、音频支持；
仅支持视觉的服务不能评 AV。

## 保持协议

- VL 顺序：timestamp/视频帧、可选参考图、Prompt。
- AV 顺序：timestamp/视频帧、完整音频、可选参考图、Prompt。
- Text 仍保留对应 track 的视频和音频，只有 Text+Image 额外带参考图。
- 使用发布版 Prompt、实际采样时间戳和全视频采样，SG 也一样；不向模型发送 GT 或整条题目记录。
- `--nframe` 和 `--fps` 二选一，帧数可以调整。
- 记录实际 thinking、token、采样和服务端设置，不默认所有模型都开 thinking；不擅自删除音频、时间戳、参考图或修改 Prompt。
- 按要求运行 Text、Text+Image 或 both；CS 使用配置一致的有效配对结果，不是两个分数的平均值。

## 运行和续跑

通过 `bash run.sh` 运行，任务用逗号分隔，每种配置使用独立输出目录。
未经验证的接口先做已获授权的小规模试跑，检查请求成功、模态支持和最终回答
可解析后再扩大；已有等效验证时，不强制重复试跑。

子集试跑与全量选择不同，需独立目录，不能承诺自动复用子集回答。
也可保持全量选择，用 `--max-requests` 限制调用；它仍会为所选视频准备帧，
去掉限制后可按原配置续跑。试跑调用计入约定预算。

只在配置、代码和媒体记录匹配时使用 `--resume`；不删除预测、改写记录或复制
子集结果来绕过检查。共享帧缓存时错开准备阶段，或使用独立缓存。
从 `progress.json`、`run.log` 汇报进度，不编造 ETA，不在没有运行监控时声称后台监控。

使用 runner 的有限重试；遇到鉴权、额度、模态不支持或持续请求失败，先停止扩大
并排查。已完成但格式错误或截断的回答按既有规则评分，不为提高分数擅自增加
预算或重跑；新的实验需获得授权并单独记录。保留拒答和失败信息，不伪造预测补齐任务。

## 评分和汇报

使用 `scores.json`、`scores.csv`。原生推理适配按协议导出 Prompt，每个题目和
设置写一条最终回答，再调用共享评分器；不直接拼接含重试的原始日志。
单设置不报告 CS，未完成的评测不作为最终结果。

汇报准确模型名、track、任务、设置、采样、完成数/总数、失败或排除项、
可用任务分数和输出路径，区分完成、阻塞和未运行。
不擅自上传结果或暴露密钥，不把环境检查说成论文复现或 GPU 实测。
